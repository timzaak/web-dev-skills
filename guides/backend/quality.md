# Backend 验收依据

公共结论、分级、报告、只读边界和结构化输出只由 `${CLAUDE_PLUGIN_ROOT}/protocols/acceptance-contract.md` 定义；验收前读取。设计适用性按 `${CLAUDE_PLUGIN_ROOT}/guides/core/quality.md`，架构与实现检查按 `${CLAUDE_PLUGIN_ROOT}/guides/backend/development.md`。本页只补充后端领域门禁。

## 必要门禁

按变更和依赖范围确定适用项：

- Rust 编译通过；受影响测试通过，必要场景无失败、跳过或零用例假通过。
- 实现符合设计中的业务规则、权限、租户/数据边界、状态转换、事务和公共 API 契约；检查本次涉及的失败及边界路径。
- 当前阶段负责的必要业务/API 场景有有效运行证据；后续承接和最终收口按验证证据协议。
- 服务项目的启动、健康检查和必要清理有有效证据，健康检查路径和响应以项目契约为准。环境验证失败不能被测试通过抵消。
- 涉及公开 HTTP/OpenAPI 契约及其生成链路时，注解、schema/路径注册、导出产物和实际消费者一致且可用；需要前端客户端的项目验证对应生成链路。没有前端或 OpenAPI 的项目记录适用性依据，不新增这些交付物。
- 项目规定的 Clippy 等门禁通过；警告按具体影响区分阻断缺陷和维护性建议，不用警告数量代替判断。

纯文档或无运行影响的机械变更按公共协议记录适用性，不要求重跑无关门禁；必要运行证据仍须有效，不能因只改少量文件跳过。

## 命令与执行范围

从目标项目配置确认 package、脚本和工作目录，已有有效证据时不重复执行。补验示例：

```bash
cd backend && cargo check --package <api-package>
uv run scripts/backend-test.py -- <targeted filter>
```

默认定向覆盖本次改动。仅用户明确要求全量，或影响范围无法可靠收敛时，升级全量 `uv run scripts/backend-test.py --`，记录原因且全量结果必须通过；不得用裸 `cargo test/nextest` 绕过项目环境和 DDL guard。

环境启停、健康检查和清理使用目标项目真实入口，不用固定睡眠代替就绪探测。重复代码检查按公共协议限定范围和触发条件，不扫描无关代码或自动安装工具。

## OpenAPI 与客户端

按实际框架及注册位置检查；使用 utoipa 时核对：

- 公开 handler 的方法、路径、tag、适用的路径/查询参数及请求体、成功/错误响应与实现一致；不为无请求体操作强制添加 body。
- 引用的请求、响应和错误类型具备适用的 `ToSchema`；`ApiDoc` 中端点、schema、tag 无遗漏。
- OpenAPI 可导出且为有效 JSON，路径/schema/tag 与当前契约一致，无旧占位符；导出位置以项目事实为准。
- 有前端客户端消费者时，核查其真实生成命令（例如 `cd frontend && npm run generate-api`）、产物和受影响消费者的类型/测试证据。

允许生成的输出及差异处理按公共验收协议。生成失败交回对应 dev；修复后重跑受影响测试、导出、客户端生成及消费者验证，不能仅以文件存在判定同步成功。
