# Figma 结构二次重建

## 为什么需要重建

Figma 的 group/frame 可能只反映设计师的画布操作，不代表组件边界、文档流或响应式关系。`get_design_context` 返回的 React-like 表达只能作为输入，不能直接复制。

## 执行顺序

1. 对齐 metadata 的绝对坐标和 screenshot 的视觉边界，识别主区域、重叠、裁切、背景与浮层。
2. 检查图片填充和文字的共同父级，标出需要合成导出的素材；排除交互或动态文字。
3. 从目标文件及邻近模块提取已有组件、token、布局容器、断点和动效模式。
4. 把视觉块映射到已有组件；Figma group 与代码组件不必一一对应。
5. 把确认后的 nodes、资产引用和探针写入 `spec.json`。不确定的结构写入候选或询问，不伪装成确定事实。

## 响应式

存在多套 Figma frame 时按明确 viewport 分别生成 probes。只有单一平面稿时，使用目标项目现有断点和布局模式适配；不得从一个桌面坐标系凭空推导新的产品行为。

fix 发现结构错误时更新二次规格并增加 revision；`source/` 原始快照保持不变，便于复盘 MCP 输入与人工重建之间的差异。
