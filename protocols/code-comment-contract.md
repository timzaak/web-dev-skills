# Code Comment Contract

本协议定义目标项目生产代码与测试代码中注释的编写约束。

默认不写注释：任何注释必须命中下文"必须保留的注释"中的至少一条，命中不了的注释不应存在。保留下来的注释用最少的词、通常一行说清一个原因或约束；复杂算法确需多行时只写依据与取舍，公共 API 文档注释按目标语言的文档格式撰写。

## 禁止引用临时工作流文档

- 注释中不得引用 `.ai/design/**`、`.ai/task/**` 的路径、章节名、item 名或步骤名。这些文件是工作流临时产物，交付后会被删除，引用它们必然产生指向不存在文件的悬空注释。
- 设计取舍、任务拆分、实现顺序属于工作流上下文，留在 `.ai/` 文档和 commit message 中，不写进代码注释。
- 确实需要长期保留的设计原因，用注释直接说明原因本身（业务规则、约束、取舍），而不是指向设计文档。

## 追溯注释

- 测试追溯注释只引用用户故事，不引用设计或任务文档。
- 追溯使用稳定 US ID，可附真实存在的 `docs/user-stories/...` 路径；发布前只有草稿时，真实路径与场景映射留在工作流文档，代码只写 US ID。唯一定位、存量路径兼容和发布后核查按 `${CLAUDE_PLUGIN_ROOT}/protocols/requirement-source-contract.md` 的 Story Traceability；不虚构正式路径，不引用 `.ai/` 临时产物。

## 禁止编写的低价值注释

编写阶段就不应产生以下注释，而不是留待提交前清理。以下列举的是高频形态，不在列表内的注释同样受"默认不写注释"约束：

- 复述函数名、变量名、类型名、文件名或目录职责的注释。
- 逐行解释显而易见语句的注释，例如"设置值""调用接口""返回结果"。
- 叙述控制流程的注释，例如"先校验参数，再调用服务""遍历列表逐个处理"。
- 分节标签、分隔线或目录式导航注释，例如"===== handlers =====""--- helpers ---"。
- 叙述本次变更经过的注释，例如"从 utils.ts 移入""新增字段""重构后的写法"；变更过程属于 commit message。
- 标记开发阶段、迁移步骤、临时分层、实现顺序，但对运行时代码没有帮助的注释。
- 与当前实现不再一致、语义空泛、只表达"这里处理逻辑"的注释。

## 必须保留的注释

- 解释业务规则、领域不变量、权限/安全边界、兼容性原因、外部协议约束的注释。
- 解释复杂算法、非直观性能取舍、并发/事务/生命周期风险的注释。
- 有明确责任人的 TODO/FIXME，或指向具体缺陷、后续任务、版本约束的注释。
- 测试追溯、license、lint/coverage 指令、生成代码标记、公共 API 文档注释。

## 兜底清理

- `/t-push` 在提交前按本协议清理本次变更文件中的注释，清理范围只限本次变更文件，不做全仓历史清理。
- 本次 diff 新增的注释逐条对照"必须保留的注释"审计：命中至少一条才允许保留，否则删除；"看起来有信息量"不构成保留理由。
- 变更文件中本次 diff 未触及的存量注释，只按禁止条款清理（临时工作流文档引用、低价值注释、违规追溯），不回溯套用保留白名单。
- 编写阶段已遵守本协议时，兜底清理应基本无活可干；`/t-push` 频繁清出同类注释说明编写侧未遵守本协议。
- 残留 `.ai/user-stories/` 注释按违规处理，由当前实现/提交清理入口改为稳定 US ID 或有效正式来源；accept 只报告，发布入口不越界修改代码。
