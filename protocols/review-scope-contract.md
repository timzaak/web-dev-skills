# Review Scope Contract

`t-review` 与 `t-simplify` 的范围收集、目标解析和修复前核对规则。收集范围前读取；具体审查角度与报告结构仍由各自契约定义。

## 默认范围

1. Git 仓库已有提交时，优先收集 `git diff '@{upstream}...HEAD'`；仅在引用不存在时依次回退 `git diff main...HEAD`、`git diff HEAD~1`。无 upstream、无 main 且首次提交没有父提交时，以空树与 HEAD 比较，不因 `HEAD~1` 不存在而漏掉初始代码。权限、仓库损坏或读取失败不能当作引用缺失而静默回退。
2. 追加 `git diff HEAD`，覆盖 staged / unstaged 变更；用 `git ls-files --others --exclude-standard` 收集未跟踪的实现、测试、配置及可执行工作流文件。排除 `.ai/`、依赖与构建产物，不把工作流 Markdown 一律视为无关文档。
3. 合并区间与工作区信息，以当前文件最终内容为准：已被工作区撤销的中间改动不算当前缺陷。报告记录实际比较基准、HEAD、文件清单及是否包含未提交变更。
4. 非 Git 仓库或尚无提交时，仅审查用户明确指定或本会话确实修改过的相关文件；没有这些依据时返回 `SCOPE_UNAVAILABLE` 并请用户指定目标，不按文件修改时间猜测范围。

## 显式目标

目标替换默认范围，不隐式拼入其他分支或无关工作区变更：

| 目标 | 范围 |
| --- | --- |
| PR 号 / PR URL | 通过可用的 PR 工具读取该 PR 的 base、head、diff 与 head 文件内容 |
| 分支名 | 解析该分支的 upstream，缺失时回退 main；比较共同祖先至目标分支 tip |
| Git revision range，如 `HEAD~15..HEAD`、`main...feature` | 按 Git 的区间语义解析，记录实际两端提交 |
| 文件 / 目录路径 | 将默认范围限制在该路径；显式指定的未跟踪文件也纳入 |

把目标作为工具参数或正确引用的 shell 参数传递，不将用户文本直接拼成 shell 代码。目标有歧义时请用户裁决；解析失败、PR 工具缺失或远端不可访问时返回 `SCOPE_UNAVAILABLE`，不得回退成审查当前分支。已成功解析但无改动时才返回 `NO_CHANGES`。

## 上下文与修复边界

- 收集后把同一份 diff、相关文件版本与项目约束交给所有 reviewer / finder / verifier；可给出获取命令，但命令必须定位已解析的提交与路径，不能让不同 agent 各自重选基准。修复前保持范围只读。
- 读取适用于变更路径的 `AGENTS.md`、`CLAUDE.md` / `CLAUDE.local.md`；按运行时边界处理约束冲突，不把托管 Code Review 服务的 `REVIEW.md` 自动当作本地审查契约。
- PR、其他分支或历史区间可以只读审查。应用修复前核对本地分支、文件内容与受审版本；不匹配时只报告并将修复记为 pending / 跳过，不能自动 checkout、覆盖工作区或把旧行号套到当前文件。
- 修复只撤销本次操作自己的改动，保留用户原有修改；重跑重新收集当前范围，不把旧报告的“干净”结论直接套到新代码。恢复同一报告时先核对范围及已经记录的修复结果。
