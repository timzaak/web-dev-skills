# Skill 测试与迭代

按变更风险选测试深度，遵守调用方明确要求的验证门禁：微调可只做写作自检和引用核对；新建或结构性大改需验证实际行为。用例覆盖受影响的正常路径、缺失前置、下游门禁、失败恢复和重复执行，不固定数量。形式校验不能替代行为证据。

## 前向行为测试

1. 从真实请求和已知失败中选用例。把问题写成可根据文件、工具结果或状态判断的断言。例如，曾误把插件缓存当源码时，断言仅有缓存且找不到源码的运行不会写入，并会请求源码位置。仅就影响意图或授权的问题询问用户。
2. 普通验证在主会话执行。只有需要确认 skill 的收益或行为变化时，才做有无 skill 或新旧版本的对照。使用相同输入、模型、运行时和工具权限，在全新会话中依次运行。对照或恢复需要旧版时，编辑前确认可从版本控制还原，或暂存无法还原的内容。
3. 复杂或高风险测试确需独立判断时，优先使用独立会话，或在可用且已获授权时使用 subagent。向执行方提供 skill、任务和必要原始输入，预期答案和失败断言留给评分方。大量只读探索可同样隔离，并交回摘要和证据路径。
4. 在隔离临时目录测试，避免影响真实项目和外部服务。按断言记录实际结果及证据，区分失败和未执行。结束后按调用方的留存约定保留复核所需证据，再清理本次产生的临时产物。

## 触发边界测试

新增入口或修改 `description` 时，按 [skill 写作准则](${CLAUDE_PLUGIN_ROOT}/guides/core/skill-authoring.md) 检查触发边界：

- 正例覆盖直接请求、间接说法及与相邻 skill 竞争的场景。
- 反例选共享关键词但目标不同的近邻请求，不凑明显无关的查询。
- 仅触发路由有误时修改 description，执行行为有误时修正文；重测受影响用例。

## 迭代准则

- 区分指令缺陷与不现实的测试输入，只按观察到的问题做窄修正，不为单个样例堆叠普遍规则。
- 删除无效内容；重复生成的确定性 helper 按需沉淀为脚本。
- 受影响门禁通过且无未解决的实质问题后交付，不为凑轮次重复测试。
