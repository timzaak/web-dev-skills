# 文档骨架模板

写具体章节时参考这里的结构。不是死模板，根据项目实际情况裁剪。

## index.md

教程入口页。让人一眼知道这是什么、给谁看的、怎么往下看。

```
# [项目名]

[一句话说清这是什么。不要写"本文将介绍"，直接说]

## 给谁看

[目标读者。比如："有 Node.js 经验的后端开发者，刚加入团队的前两周"]

## 前置知识

[看这个教程之前需要了解什么。没有就写"无特殊前置要求"]

## 章节

- [快速上手](getting-started.md) — 从零到跑起来
- [架构](architecture.md) — 项目结构和技术选型
- [API 参考](api-reference.md) — 接口文档（如果项目有 API）
- [配置](configuration.md) — 配置项说明
- [部署](deployment.md) — 怎么上线
```

## getting-started.md

目标是让新人在 30 分钟内把项目跑起来。

```
# 快速上手

## 你需要先装好

[具体版本号。比如 Node >= 18, PostgreSQL >= 14, Redis >= 7]

## 安装

[实际命令，能复制粘贴直接跑。不要写"执行以下命令"，直接给命令块]

## 配置

[必须改的配置项，用代码块或表格。标注哪些是必填]

## 运行

[启动命令 + 默认地址/端口等实际信息]

## 验证

[怎么确认跑起来了。比如"打开 http://localhost:3000/health 应该返回 ok"]
```

如果安装过程中有常见坑，加一段"常见问题"。只写真会遇到的问题，不要编。

## architecture.md

让人理解项目为什么长这样，而不只是长什么样。

```
# 架构

[一句话总览]

## 目录结构

[实际的目录树。只列关键层，不要把每个文件都列出来]

## 技术栈

[用到的关键技术，一行列完。比如：Node.js 18 + Express + PostgreSQL 14 + Redis 7]
[只在选型直接影响使用者操作时才说明理由，比如"用 RabbitMQ 而不是 Redis Streams 是因为需要消息持久化，你需要在本地装 RabbitMQ"]

## 核心流程

[关键业务的数据流或调用链。用代码示例、文字描述、或 Mermaid 图]

如果用 Mermaid，格式：
```markdown
​```mermaid
flowchart TD
    A[请求入口] --> B{认证检查}
    B -->|通过| C[业务处理]
    B -->|失败| D[返回 401]
​```
```

只在流程确实比文字更清楚时才画图。

## 模块说明

[每个主要模块干什么，和其他模块什么关系]
```

**响应示例：**

[从代码或测试里提取的实际 JSON，不要编造]

**请求示例：**

[curl 命令或代码片段，能直接跑]
```
