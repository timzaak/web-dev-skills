# Figma 结构二次重建

## 原则：截图定结构，节点树补数值

Figma 的 group/frame 层级与绝对坐标可能服务于画布编辑，不直接对应 DOM；Auto Layout、约束、组件和文本缩放属性仍可能表达有效设计意图。结合两类证据重建：

1. **截图定结构**：以 baseline 截图为主证据划分视觉块（header、hero、features…），识别块边界、stacking、重叠、裁切、绝对定位与合成素材。截图回答"页面上有什么、长什么样"。
2. **节点树补事实**：用 MCP 补尺寸、颜色、变量、字号/字重、文本内容，以及显式布局属性和交互标注。截图不能证明响应式或交互规则；不把节点层级映射成组件层级。

## 执行顺序

1. 先看截图划分主区域，再对照 metadata 绝对坐标确认重叠、裁切与浮层。
2. 识别不可拆的营销合成素材，排除交互、动态或本地化文字；素材准备按 `${CLAUDE_PLUGIN_ROOT}/guides/figma/assets.md` 的「合成含文字图片」处理，impl 只记录并引用，不自行导出。
3. 从目标文件及邻近模块提取已有组件、token、布局容器、断点和动效模式；视觉块映射到已有组件，Figma group 与代码组件不必一一对应。
4. 在 MCP 窗口内为主节点和每个视觉块调用 `get_screenshot` 保存 `source/baseline[-<block>].png`，作为逐块实现和人工验收比对的视觉基准；metadata、design context 和 variables 不落盘。
5. 按 `${CLAUDE_PLUGIN_ROOT}/protocols/figma-workflow-contract.md` 的「布局决策与恢复」记录块清单、原始观测、采用规则及待裁决项，再进入实现；agent 输出与裁决恢复也以该契约为准。

## 尺寸语义

先区分测量结果和布局规则：节点宽 368px 只说明当前尺寸，不能单独证明应该固定宽；与视觉一致的 Auto Layout、约束、文本缩放和组件规格则可作为布局依据。已有规则直接承接，缺失规则时结合视觉关系与项目模式推断；多种合理解释会改变结果时提交待裁决项。

- 缺少显式 sizing 规则且视觉关系支持时，流式容器随父容器伸缩（fill），窄内容按内容收缩（hug），高度由 padding 与内容撑开；用 min/max 表达可证实的上下限，避免整页套画布坐标。
- fixed 按证据保留，不按元素名称一刀切：组件规定的按钮高度、侧栏宽度、等高卡片，以及头像/图标尺寸都可能有效。宽高比用比例约束表达；重叠装饰和浮层可局部绝对定位，不强行塞进文档流。
- 文本区域结合字体、行高、宽度及显式换行/截断规则还原；不能把当前文本框高度直接当容器高度，也不能为追求自适应取消有意的裁切或截断。
- 间距与圆角优先使用已有变量绑定或项目明确的 token 映射/容差。无映射依据时保留观测值，不因接近 4/8 倍数而自动吸附；只消除有依据的浮点或像素取整噪声，调整前后值与依据写入采用规则。映射与视觉证据冲突时提交裁决。

例如，测量宽 368px 的卡片在项目三列 Grid 中可随列宽伸缩；组件明确规定 44px 高的按钮可保留该高度。两者都需引用对应布局或组件依据，不能仅凭“卡片/按钮”的名称决定。

## 响应式

存在多套 Figma frame 时按明确 viewport 分别记录各稿基准。只有单一平面稿时，使用适用的项目现有断点和布局模式；缺少适配依据且必须决定隐藏内容、改变阅读顺序或替换导航等行为时提交裁决，不从桌面坐标系推导新的产品规则。

实现中发现结构错误时按契约「布局决策与恢复」修正对应块定义；`source/` 的 baseline 快照一次写入后保持不变，MCP 原始响应不落盘，复盘以 `context.md` 与快照对照为准。
