# Skill 测试与迭代

按变更风险选测试深度，遵守调用方明确要求的验证门禁：微调可只做写作自检和引用核对；新建或结构性大改需验证实际行为。用例覆盖受影响的正常路径、缺失前置、下游门禁、失败恢复和重复执行，不固定数量。形式校验不能替代行为证据。

## 前向行为测试

1. 从真实请求和已知失败中选用例，提供必要路径、上下文与输入。仅在意图不明或执行需要额外授权时询问用户，不要求逐例过目。
2. 复杂或高风险流程在可用且已获授权时用独立 subagent 执行，只提供 skill、任务和必要输入，不透露预期答案或怀疑的缺陷；其余情况可直接执行并记录证据。测试在隔离临时目录进行，结束后清理，不影响真实项目或外部服务。
3. 评估可观察的行为和产物：是否完成任务、遗漏门禁或越界。只有需要确认 skill 的实际收益或行为变化时，才比较有无 skill 或新旧版本；对照使用同一输入，并保留所需旧版快照。

## 触发边界测试

新增入口或修改 `description` 时，按 [skill 写作准则](${CLAUDE_PLUGIN_ROOT}/guides/core/skill-authoring.md) 检查触发边界：

- 正例覆盖直接请求、间接说法及与相邻 skill 竞争的场景。
- 反例选共享关键词但目标不同的近邻请求，不凑明显无关的查询。
- 仅触发路由有误时修改 description，执行行为有误时修正文；重测受影响用例。

## 迭代准则

- 区分指令缺陷与不现实的测试输入，只按观察到的问题做窄修正，不为单个样例堆叠普遍规则。
- 删除无效内容；重复生成的确定性 helper 按需沉淀为脚本。
- 受影响门禁通过且无未解决的实质问题后交付，不为凑轮次重复测试。
