# Banner/Hero 块 UI 适配

banner、hero、活动头图等整幅大图块实现时的适配规则。适配体系（断点、缩放机制、素材命名、文案来源）一律沿用目标项目已有定义，不从 Figma 坐标推导。

## 双端与缩放

1. 每处布局属性（定位、对齐、字号、间距、宽高、裁切焦点）双端各有值：一端为默认，另一端以项目断点变体或 media query 覆盖，不留只写单端的属性。
2. 端差异优先纯 CSS：media query 与 `<picture>`/`<source media>` 由浏览器选择，两套内容同时输出；JS 只用于开关交互行为（如触屏手势），不用 JS 切换 DOM 或样式。
3. 落值前先识别目标项目的缩放体系：流式根字号（`html font-size` 随视口计算）时按设计稿 rem 直接落值，整幅随视口等比缩放；没有时按断点写双值。局部成组缩放（标题、文案、间距按同一比例联动）用容器上的 CSS 变量单位 `calc(n * var(--unit))` 表达，并用 `max()`/`min()` 保上下限。

## 布局与媒体

1. 媒体区双端各声明宽高比防变形；某端改固定高时同时取消该端的比例约束。
2. 数值范围用 clamp/min/max 限定；内容容器用项目页宽 token；悬浮于页面边缘的元素（轮播箭头等）相对页宽定位，不贴死视口。
3. 高度随运行状态切换用状态类或属性选择器表达，不用 JS 改内联样式。
4. 图片按端备料：移动/桌面各一套素材（命名按项目约定），`<picture>` + media 条件输出，srcset/sizes 按真实占宽写；尺寸未知时用宽高比占位防抖动。
5. 加载分级：首屏首帧 eager + 高优先级，其余 lazy；视频进入视口前不加载。移动端有独立视频源时同样按 media 条件输出。
6. 裁切焦点双端各自声明：默认居中裁切，移动端需要保住主体或完整呈现时单独给 object-position/object-fit。

## 文案与按钮

1. 字号双端各有值并保最小可读下限；受宽高约束的文案显式声明换行/截断（单行省略、多行截断 + 固定高），有意截断不取消。
2. 多语言文案外置 locale 文件；语种长度差异影响布局时按语言单独调整字号或换行。
3. 移动端触控目标不小于 44px。

## 数据驱动

多 slide 的集合与顺序、分端对齐/高度等由配置项或数据源驱动，不硬编码进模板；多市场/多语言跳转链接按市场或域名切换。Figma 不提供这些数据来源：target-file 已有该模式时沿用，没有且必须新增时提交裁决。
