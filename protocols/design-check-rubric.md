# Design Check Rubric

## Scoring

总分 100：

| 维度 | 分值 | 说明 |
|---|---:|---|
| 需求追溯性 | 20 | 与用户故事、PRD 或技术预研的目标、边界、术语一致 |
| 现有实现分析准确性 | 15 | 使用真实路径，复用点与受影响范围明确 |
| API 设计完整性 | 20 | 接口清单、字段、错误响应、权限和路径规范完整 |
| 数据库设计完整性 | 20 | 表/字段、类型、约束、索引、迁移策略明确 |
| 前端设计完整性 | 10 | 页面/组件、线框说明、状态与数据依赖明确 |
| 测试与验收策略 | 10 | 后端/前端/Demo 测试入口和主验收路径明确 |
| 文档规范与假设显式化 | 5 | 结构稳定、假设清晰、风险可追溯 |

## Clarification Gate

设计生成或设计检查过程中，凡问题会影响目标范围、业务规则、权限/安全边界、API 契约、数据模型、迁移/兼容性、验收标准或测试策略，且无法从 PRD、用户故事、技术预研、仓库事实或用户已给上下文裁决时，必须停止并使用 `AskUserQuestion` 向用户提问。

要求：

- 不得把这类问题仅写入 P0/P1/P2、风险表、待确认事项或假设后继续推进。
- 问题必须给出证据、具体决策点和被阻塞的后续动作。
- 用户回答后，先更新设计文档，再继续评分或进入 `/t-task`。
- 未得到用户回答前，不得给出“通过设计验收”或“可进入后续拆解”的结论。

已由证据确认的问题继续按 P0/P1/P2 记录；必须由用户裁决的问题状态为 `needs_user_answer`，不参与 P0 计数。

## Severity Rules

### P0

- 设计文档不存在
- 涉及后端接口但缺少 API 设计
- 涉及数据库变更但缺少数据库设计
- 涉及前端但缺少页面/交互说明
- 业务功能设计目标与 PRD/用户故事明显冲突
- 纯技术方案设计目标与引用的技术预研明显冲突
- 使用不存在的仓库路径作为依据

### P1

- API 路径、权限模型、关键字段命名与仓库规范严重不一致
- 数据库字段类型、约束或迁移策略不明确
- 数据库设计明显过度
- 前端页面描述过于抽象，缺少页面区域、交互或状态
- 测试策略缺少实际入口
- §8 文件影响范围章节缺失，或文件路径使用未验证的示例路径

### P2

- 可复用点说明不够聚焦
- 非阻塞风险或已解决待确认事项不够具体
- 示例与字段表轻微重复，可压缩

## Detailed Checks

需求追溯：

- 业务功能设计应引用用户故事或 PRD，并保持目标、业务边界、术语一致
- 纯技术方案设计可只引用 `.ai/tech-research/<feature>.md`，但必须明确声明不涉及业务逻辑、产品规则、用户可见流程或验收目标变动
- 如果设计包含业务逻辑、产品规则、用户可见流程或验收目标变动，不能仅依赖技术预研，必须回到 PRD/用户故事链路
- 技术预研作为唯一来源时，检查设计是否承接技术目标、依赖决策、影响范围、风险和显式假设

API：

- 至少包含方法、路径、用途、权限/身份、调用方
- 关键接口包含请求字段、响应字段、错误响应或状态码
- 路径参数占位符使用 camelCase
- 明确新增 DTO 与复用 DTO 的边界

数据库：

- 涉及时给出表/字段变更清单
- 关键表说明字段、类型、主键、唯一约束、必要索引、外键、时间字段
- 说明迁移策略和兼容性影响
- 默认保持简洁，不预埋不必要复杂审计方案

前端：

- 涉及时给出页面/组件清单
- 给出页面区域、主要交互、关键状态、数据来源或依赖
- 说明与现有前端模式的承接关系

文档结构：

- §8 文件影响范围章节必须存在，表格包含 `文件 | 操作 | 说明` 三列，操作列使用 CREATE/MODIFY/DELETE
- §5 详细设计章节必须存在（即使内容是"不适用"），用于放置具体数据结构与函数签名
- §7 风险与待确认事项只记录非阻塞风险、已回答的确认事项或明确不影响设计方向的问题，使用 `| 风险项 | 等级 | 缓解措施 |` 三列表格，等级标注 P0/P1/P2
- 所有文件路径必须为仓库真实路径，不得出现 `backend/src/...` 这类未验证的示例路径

## Report Requirements

报告必须包含：

- 总分、等级、是否通过设计验收
- 用户澄清状态：无阻塞澄清 / 已通过 `AskUserQuestion` 解决 / 等待用户回答
- 每个维度得分与证据
- P0/P1/P2 问题列表
- 需用户回答的问题清单：`问题 | 证据 | 需要用户决定什么 | 阻塞的后续动作`
- 明确修复步骤

等级建议：

- `90-100`: 优秀，可进入后续拆解
- `75-89`: 良好，建议先修 P1
- `60-74`: 需改进，必须修 P0
- `<60`: 不合格，建议重写关键章节
